Wozu ein Token?

Mit einem Fine-grained Personal Access Token erkennt GitHub Deine API-Abfragen als authentifiziert. Dadurch steigt das reguläre Stundenkontingent in der Regel von 60 auf 5'000 Anfragen. Für öffentlich lesbare Daten sind keine zusätzlichen Repository-Rechte nötig. Erstelle einen eigenen Token mit möglichst wenigen Rechten (nur automatisch vorhandenes «Metadata: Read-only»), zum Beispiel eingeschränkt auf ein einzelnes Repository.

Der Token wird nur in diesem Browser gespeichert und bei API-Anfragen an api.github.com gesendet. Auch ein Token ohne zusätzliche Rechte ist ein Geheimnis: JavaScript derselben Website und Personen mit Zugriff auf Dein Browserprofil könnten ihn auslesen. Nur auf vertrauenswürdigen Geräten speichern. Er wird weder in die HTML-Datei noch in den Konfigurationsexport übernommen. Die Verwendung und lokale Speicherung des Tokens erfolgt auf eigenes Risiko. Bei Verdacht auf Missbrauch den Token bei GitHub widerrufen. Die API-Abfragen bleiben lesend.

Hinweise zur Interpretation

Die Überwachung startet erst nach Klick auf «Abfrage starten». Ein GitHub-Cron wird aus öffentlich lesbaren Workflow-Dateien erkannt. «Kein GitHub-Zeitplan» bedeutet nicht zwingend «nie automatisch»: Externe Dienste wie cron-job.org können Workflows über die API starten. Der Rhythmus des externen Dienstes lässt sich daraus nicht zuverlässig ablesen. GitHub Pages wird zuerst am Repository-Merkmal has_pages erkannt; es wird kein Veröffentlichungslink abgefragt. Andere Hosting-Anbieter werden nicht automatisch erkannt.
Technische Details und Grenzen anzeigen

Die Seite nutzt die öffentliche GitHub REST API. Ein optionaler, lokal gespeicherter Token ermöglicht authentifizierte Leseanfragen. Anonyme Abfragen sind pro Aktualisierung auf 45, authentifizierte auf 300 begrenzt; bei höchstens 10 verbleibenden Anfragen wird gestoppt. Erfolgreich geprüfte Repositories bleiben 12 Stunden lokal gespeichert. Bei grossen Accounts wird die Übersicht schrittweise vervollständigt. Standardmässig können anonyme Abfragen nach etwa 60 Requests pro Stunde und IP begrenzt werden. Mehrere Accounts mit vielen Repositories können dieses Limit erreichen. Vollständige Account-Daten werden 15 Minuten lokal zwischengespeichert. Zeitangaben sind Schweizer Ortszeit. Wenn ein API-Aufruf fehlschlägt, erscheint eine Warnung statt einer erfundenen Statusmeldung. Die Seite führt keine Änderungen auf GitHub durch.
