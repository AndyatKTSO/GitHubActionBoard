Wichtig zu den Zeitplänen

Ein GitHub-Cron wird aus der Workflow-Datei gelesen. Bei «Manuell / extern möglich» ist kein GitHub-Zeitplan definiert; ein externer Dienst wie cron-job.org kann die Action trotzdem regelmässig auslösen. Den externen Zeitplan kann die öffentliche GitHub-API nicht erkennen.
GitHub Pages «pages build and deployment» wird durch Veröffentlichungen ausgelöst und benötigt normalerweise keinen Cron. Diese Übersicht liest nur öffentliche Daten, ändert nichts und benötigt keinen Token. GitHub begrenzt anonyme API-Aufrufe auf üblicherweise 60 pro Stunde und IP-Adresse. Ein Ergebnis wird 15 Minuten im Browser zwischengespeichert. Zeitangaben werden in Schweizer Ortszeit angezeigt.
Wie funktioniert die Übersicht technisch?

Pro öffentlichem Repository lädt sie die Liste der Workflows und die letzten Workflow-Ausführungen über die GitHub REST API. Aus den öffentlich zugänglichen YAML-Dateien unter .github/workflows liest sie Cron-Angaben. Es werden keine Zugangsdaten übertragen oder gespeichert. GitHub-interne Workflows ohne eigene YAML-Datei werden separat erkannt. Bei einem API-Fehler werden unvollständige Daten ausdrücklich ausgewiesen.
